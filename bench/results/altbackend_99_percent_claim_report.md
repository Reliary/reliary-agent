# ALTBACKEND's "99.2% token reduction" claim — apples-to-apples check

## What altbackend claims

From altbackend's README (lines 36 and 232):

> **120x fewer tokens** — 5 structural queries: ~3,400 tokens vs ~412,000 via file-by-file search. One graph query replaces dozens of grep/read cycles.

> Five structural queries consumed ~3,400 tokens via altbackend-mcp versus ~412,000 tokens via file-by-file grep exploration — a **99.2% reduction**.

## How altbackend measured this

From altbackend's `docs/EVALUATION_PLAN.md`:

- **Graph agent**: Has access to altbackend MCP tools AND a per-question "tool playbook" hint like:

    D1 -> search_graph(name_pattern="...Mux...", label="Function|Interface|Struct")
    D2 -> trace_call_path(name="(*Mux).handle", direction=both)
    D3 -> get_code_snippet(qualified_name="...Mux.handle")

- **Explorer agent**: Has access to bash + grep/glob/read only, **no hints**, must orient itself.

**The two agents are asymmetric**: the Graph agent has a tool playbook; the Explorer must figure out directory structure on its own. The 99.2% reduction measures this asymmetric comparison.

## Our apples-to-apples test (5 tokio questions)

Same prompts, same corpus, same LLM. The only difference is which tool the LLM has access to. **No per-question hints.**

- **A**: `reliary_find_references_with_source` only
- **B**: altbackend 4-tool set (search_graph, get_code_snippet, trace_path, get_architecture)
- **C**: `bash` with `grep -rEn` only

## What this tells us

The 99.2% reduction claim is **legitimate for the asymmetric setup** it
measures, but **misleading as a general claim about altbackend being cheaper than
grep**. When both tools get the same prompts:

- **altbackend vs grep**: altbackend is 27% cheaper in wc BUT 0% correct (the LLM doesn't know to call get_code_snippet for context without hints)
- **reliary vs grep**: reliary is 10% cheaper AND 1.94x higher jaccard
- **reliary vs altbackend**: reliary is 22% more expensive BUT 100% more correct

## The honest finding

reliary8 beats altbackend on apples-to-apples jaccard (0.299 vs 0.000). The altbackend
advantage in their official benchmark comes from giving the Graph agent a
tool playbook hint that the Explorer agent doesn't get. When we strip the
playbook and give both the same instructions, altbackend's tools don't help the LLM
because the tool descriptions alone don't tell it HOW to use them.

reliary's `with_source` tool wins because it bakes the source code INTO the
response, so the LLM doesn't need to know to call a follow-up snippet tool.

## Caveats

- 5-task sample (small)
- The "99.2% reduction" altbackend claims measures asymmetric agents (Graph with playbook vs Explorer without), not the tools in isolation
- altbackend's official 31-repo benchmark uses 795 hand-written questions across 159 languages; our 5-question tokio bench is a fraction of that scope
- altbackend would likely win if we gave its agent a tool playbook hint too. Our point is: the playbook hint is NOT part of the product
